2.4.0
- Renamed the add-on display name to ABC iView+ so it is clearly distinguishable from the older Aussie Add-ons ABC iview add-on.
- Increased the lightweight scheduler heartbeat from 0.5 seconds to 1.0 second. This heartbeat checks only in-memory deadlines, abort state and the cross-interpreter wake token; it does not poll Kodi list views or call library work.
- Kept the existing plugin.video.abc_iviewjc add-on ID, settings, generated library paths and ABC iView Library media-source name for seamless in-place upgrades.

2.3.4
- Kodi's built-in Update library command now triggers one delayed ABC iView qualification and catalogue reconciliation after the external scan finishes.
- If reconciliation changes generated files, exactly one add-on-owned scan follows; add-on-owned scan completion and Kodi cleanonupdate cleans are ignored as refresh triggers.
- Added explicit clean ownership tracking so an unrelated automatic clean cannot be mistaken for an add-on-requested clean.
- Missing/expired Kodi episode rows now use a ten-minute exponential backoff, capped at six hours, instead of keeping the service on a one-second work cycle.
- Failed batched episode-state writes are delayed for 30 seconds before retrying.
- A transient library tick, JSON-RPC or filesystem failure no longer terminates the background service; the transaction is retried after 30 seconds.
- Added a 60-second on-disk request safety check for missed cross-interpreter wake tokens. It does not call library work unless a real request file exists and does not poll Kodi list views.
- Scan and clean ownership/state are recorded before JSON-RPC starts, preventing unusually fast notifications from racing transaction setup.

- Catalogue work no longer clears an independently pending Kodi watched-state debounce job.
